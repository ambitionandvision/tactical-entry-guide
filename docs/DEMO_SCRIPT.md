# DEMO_SCRIPT — Tactical Entry Guide 시연 영상

이 문서는 **시연 영상**(에뮬레이터 화면 녹화, 가로 1920×1080, 약 135초)을 다룬다. **숏폼**(30초~1분 세로 영상)은 별도 이벤트이며 마지막 절에 따로 적었다. 두 가지를 섞어 쓰지 않는다.

## 원칙

- **영상은 Pleos 에뮬레이터 화면 녹화다.** (공식 Pleos Connect v2.1.0 이미지, Android 14 / API 34, 2560×1440, cold boot)
- **본편(ICE)의 차량 이동은 실주행 로그 재생이다.** 2026-11-13 아반떼 CN8 가솔린으로 주행하며 스마트폰 GPS 로거(1Hz)로 기록한 위치를 에뮬레이터의 앱에서 재생한다. 화면에 앱 라벨 "실차 GPX 주행 재생" 이 보인다.
- **보조(EV) 영상의 차량 이동은 시뮬레이션 GPX 재생이다.** 화면에 앱 라벨 "GPX 주행 재생 (시뮬레이션)" 이 보인다.
- 앱을 차량에 설치해 실행한 영상이 아니다. "실차 검증", "실차 탑재" 로 읽히는 자막·설명을 쓰지 않는다. 실차 내부 촬영, 실차처럼 보이게 하는 연출(핸들·도로 실사 합성 등)도 하지 않는다.
- 디스플레이 크기 등 차량 사양을 자막에 쓰지 않는다.
- 개인정보(성명·연락처·이메일·소속)와 코스트코·현대·Pleos 로고를 넣지 않는다. 시설명은 대상지 식별용 텍스트로만 쓴다.
- 이 시설의 램프 입구에는 차단기가 없다(2026-11-13 현장 확인). 차단기가 있는 것처럼 읽히는 자막을 쓰지 않는다.
- 화면은 **밝은 테마**(주간)다. 밝은 회백색 바탕, 흰 카드, 파란 강조색, 회청색 도로, 주황색 본관, 파란 유도 리본과 램프. 실제 Pleos 화면과 어울리게 한 것이다. 야간 모드용 어두운 테마는 구현했지만 에뮬레이터에서 확인하지 않았고 영상에 나오지 않는다.
- Phase 2 HUD 에는 추천 차선, 입구까지 거리, 차선 이탈 경고만 있다. 높이 제한 2.1m·회차불가·대기차로는 3D 지도 위의 핀과 라벨, Phase 1 요약 카드에 나온다.

## 파일 (2026-11-14 밤 녹화, 밝은 테마 최종 빌드, 개발 PC 의 Pleos 에뮬레이터)

| 영상 | 파일 | 길이 | 크기 | 형식 |
|---|---|---|---|---|
| 본편 (내연기관, 옥상 주차장 램프 입구, 실주행 로그 재생) | `docs/demo/tactical_entry_guide_ice.mp4` | 134.99초 | 79,768,810 바이트 (약 76MB) | 1920×1080 h264, 6Mbps |
| 보조 (EV, 충전소 인접 입구, 시뮬레이션) | `docs/demo/tactical_entry_guide_ev.mp4` | 135.01초 | 66,598,057 바이트 (약 64MB) | 1920×1080 h264, 6Mbps |

- 두 영상은 **편집하지 않은 한 번의 연속 녹화**다. 자막, 타이틀 카드, 배속, 컷 편집이 없다. 녹화 중 앱을 조작하지 않았다(녹화 후 앱 로그로 재생 시작 1회, 도착 1회, 조작 0회를 확인).
- 영상 파일 안의 프레임은 직접 열어 보지 못했다(개발 PC 에 ffmpeg 가 없다). 녹화 중 60초와 132초 시점의 화면을 따로 받아 확인했다.
- 두 영상은 최종 release 빌드(패키지명 `io.github.ambitionandvision.tactical`, 밝은 테마, 전체 보기의 차량 마커 확대, 이탈 경고 문구 줄바꿈 수정 포함)로 녹화했다.
- 최종 영상의 녹화 중 프레임률(5초 구간 기준)은 본편(ICE) 57.2~60.0fps, 보조(EV) 57.7~60.0fps 이고 55fps 미만 구간이 없다. 본편 재생은 시작부터 도착까지 110.4초였다.
- 녹화 중 PC 부하가 높을 때는 46~54fps 까지 떨어진 회차가 있었고, 부하를 줄인 뒤 다시 녹화했다. 본편은 다섯 번째 녹화본이다. 그때 PC 의 CPU 사용률은 19% 였고, 46~54fps 구간이 나온 직전 회차는 52% 였다. 같은 APK 다.
- 2026-11-05 녹화본은 입구 수정 전의 경로와 라벨이라 쓰지 않는다.

## 재현 명령

```bash
# 1) 에뮬레이터 cold boot + APK 설치·실행 (위치는 앱 내장 GPX 재생)
bash scripts/run_emulator_demo.sh --fuel ICE

# 2) 원클릭 녹화: 앱 재실행 → Driving View 속도를 GPX 에 맞춤 → screenrecord → docs/demo/ 로 회수
bash scripts/record_demo.sh --fuel ICE --secs 135     # tactical_entry_guide_ice.mp4
bash scripts/record_demo.sh --fuel EV  --secs 135     # tactical_entry_guide_ev.mp4

# 3) 주행 제한만 따로 재현할 때 (Virtual Console: 기어 D, 25km/h, 8초 유지 후 자동으로 P 복귀)
python3 scripts/virtual_console_drive.py --gear Drive --speed 25 --hold 8 --watch-uxr
```

- 비트레이트 기본값은 6Mbps 다(135초에 약 64~83MB, GitHub 파일 한도 100MB 아래). screenrecord 는 한 번에 최대 180초다.
- Windows 에서는 `scripts\run_emulator_demo.bat`, `scripts\record_demo.bat --fuel ICE` 를 쓴다(기본 135초, 6Mbps). 수정 후의 `.bat` 은 실행해 보지 않았다.
- 녹화 스크립트는 녹화 후 앱 로그를 검사해, 재생 시작·도착이 각각 1회가 아니거나 조작·일시정지 기록이 있으면 종료코드 7 로 끝난다. 그때는 다시 녹화한다. **녹화 중 에뮬레이터 창을 마우스로 건드리지 않는다.**

주행 제한은 Virtual Console 로 재현된다. 통합 측정(2026-11-05)에서 기어 D + 25km/h 일 때 앱이 `DO:true, UxR:80`(NO_VIDEO + NO_SETUP) 을 받았고, 리본 흐름이 멈춰 0.6초 간격 프레임 차이가 0픽셀이었다. 앱은 118초 동안 차단 없이 최상위를 유지했다.

## 궤적 기준 시간

| GPX | 종류 | GPX 길이 | 에뮬레이터 재생 실측 (2026-11-14) |
|---|---|---|---|
| 주 경로 | 실주행 로그 (2026-11-13 17:34:21~17:36:15 KST, 115점) | 114초 | 시작 입구 385m → 13.0초에 Phase 2(345m) → 110.4~111.7초에 Phase 3 도착(입구 13m). 10회 재생 |
| EV 경로 | 시뮬레이션 (113점, 768m) | 112초 | 시작 입구 541m → 38초에 Phase 2(297m) → 103.4~103.7초에 Phase 3 도착(입구 10m). 4회 재생 |

- 주 경로가 입구 500m 가 아니라 385.6m 에서 시작하는 것은 마지막 신호 대기를 마치고 출발하는 시점부터 로그를 잘랐기 때문이다. 실주행 로그에서 차량은 램프 입구에서 멈추지 않는다.
- 카메라가 차량 후방 추종으로 바뀌는 시점은 재생 약 90초다(직선거리 100m, 미리보기 계산값).

- **HUD 의 "입구까지" 는 유도선을 따라 남은 거리다.** 직선거리가 아니다. 이 접근 경로는 블록을 돌아 들어가므로 두 값이 크게 다르다(예: 쿼터뷰 화면에서 직선 150m 일 때 경로상 439m). 데모 바의 "거리 N m" 는 직선거리다. Phase 전환과 카메라 전환은 직선거리 기준이다.
- 녹화 중 Driving View 는 기어 D 이고 속도가 GPX 를 따라간다(최대 46.7km/h). 이 상태에서는 주행 제한이 걸려 리본이 흐르지 않고 정적 화살표로 보일 수 있다. 녹화 중의 주행 제한 값은 기록하지 않았다.
- 위험요소는 HUD 가 아니라 지도 위의 핀과 라벨로 나온다. "옥상 주차장 램프 입구"·"대기차로" 라벨(쿼터뷰)과 "회차불가" 핀·붉은 벽, 보라색 대기차로 핀(후방 추종)은 2026-11-14 밤 에뮬레이터 화면으로 확인했다.

## 편집본을 만들 때 넣을 수 있는 컷 (선택, 현재 영상에는 없음)

화면 캡처는 `docs/screens/` 에 있다(2560×1440, 2026-11-14 밤, 밝은 테마 최종 빌드).

| 컷 | 자료 | 자막 |
|---|---|---|
| 주행 제한 | `phase2_driving_restricted_D.png` (Driving View D 17 km/h, 앱 Phase 2, 입구까지 253 m) 또는 재현 명령 3) | "기어 D · 주행 중 → 주행 제한 수신, 애니메이션 정지 (distractionOptimized + CarUxRestrictions)" |
| 차선 이탈 경고 | `phase2_offroute_warning_landscape.png`, `_portrait.png`. 실행 인자 `--ei laneTestAtSec 38` (아래) | "시연용 실행 인자로 만든 인위적 이탈 (실주행 로그에는 이탈이 없음) · 20m 이상 벗어나면 경고, 15m 이내 복귀 시 흡착" |
| 램프 근접 | `phase2_ramp_approach_landscape.png` (입구까지 33 m, 파란 램프와 흰 쉐브론, "높이 제한 2.1m"·"회차불가" 라벨) | "높이 제한 2.1m (현장 확인) · 차단기 없음 · 램프는 옥상 주차장으로 이어짐 (형상은 실주행 로그의 위치·고도 기반 근사)" |
| 세로 창 | `phase1_summary_portrait.png`, `phase3_arrived_portrait.png` | "창 1개(portrait)·2개(landscape) 반응형" |

- 차선 이탈 경고 테스트 버튼은 데모 바에서 뺐다. 시연용 버튼이라 운전자 화면에 둘 이유가 없다. 이탈 경고 기능은 그대로이고, 시연할 때는 실행 인자로 켠다. 재생 시작 N 초 뒤부터 5초간 차량이 유도선에서 25m 옆으로 밀린다.

  ```bash
  adb shell am start --user 10 -n io.github.ambitionandvision.tactical/.MainActivity --es fuel ICE --ei laneTestAtSec 38
  ```

  - `--es fuel ICE|EV` 와 함께 쓴다. 없으면 연료 판별로 GPX 가 바뀌는 순간 예약이 취소될 수 있다.
  - 쿼터뷰에서 보이게 하려면 N 을 14~80 사이로 준다. 4차 확인에서 약 38초 시점에는 경고가 떴고, 약 60초 시점(유도선이 되돌아오는 구간)에는 뜨지 않았다.
  - 이탈 중에는 HUD 의 "입구까지" 거리가 약 90m 커진다(캡처 화면: landscape 449 m, portrait 427 m). 25m 옆으로 밀린 위치에서 가장 가까운 유도선 지점이 앞 구간으로 잡히기 때문이다.
- 2배속 구간을 쓰면 자막 옆에 "×2" 를 표시한다.

## 선택 컷 — Pleos 측위 경로

앱 내장 재생 대신 Pleos FusedLocation 을 거쳐 Phase 가 바뀌는 것을 보여주려면 GPX 를 에뮬레이터 위치로 주입한다. 통합 측정(2026-11-05, 입구 수정 전 합성 GPX)에서 `adb emu geo fix` 주입 → FusedLocation → ProximityAlert ENTER → 연속 측위 구독 → Phase 1→2→3 이 확인됐다. 새 데이터로는 다시 재지 않았다. 이때 앱은 `source=fused` 인텐트 값으로 실행해야 데모 재생 소스를 쓰지 않는다.

```bash
# 앱을 Pleos 측위 모드로 실행 (인텐트 extra: source=fused, fuel=ICE)
adb shell am start --user 10 -n io.github.ambitionandvision.tactical/.MainActivity --es source fused --es fuel ICE
# GPX 를 1Hz 로 adb emu geo fix 주입
python3 -c "import sys,xml.etree.ElementTree as E;[print(e.get('lon'),e.get('lat')) for e in E.parse(sys.argv[1]).iter() if e.tag.endswith('trkpt')]" \
  gis_data/sejong_costco_cn8_drive.gpx | while read -r lon lat; do adb emu geo fix "$lon" "$lat"; sleep 1; done
```

`run_emulator_demo.sh --inject` 도 같은 방식으로 주입하지만, APK 가 있으면 앱을 기본(데모 재생) 모드로 다시 실행하므로 이 컷에는 위 명령을 쓴다. WSL 에서는 `adb` 대신 Windows SDK 의 `adb.exe` 경로를 쓴다.

이 컷을 넣으면 자막에 "실주행 로그(스마트폰 GPS 기록)를 에뮬레이터 위치로 주입" 이라고 밝힌다. 차량 GNSS 측위가 아니라 기록한 좌표를 에뮬레이터에 넣는 것이다.

## 숏폼은 별도다

출처: 공식 온라인 설명회(2026-10-28)와 공식 홈페이지(2026-11-14 확인). 제출 전에 홈페이지에서 직접 다시 확인한다.

- 숏폼 챌린지는 본 심사와 별도인 이벤트이고 **본 심사 가산점이 없다.** 가산점이 있는 선택 제출물은 앱 시연 영상·에뮬레이터 화면 녹화와 GitHub(소스와 APK)다.
- 숏폼 규격: 30초~1분 **세로** 영상, 인스타그램 릴스 또는 유튜브 쇼츠에 게시, 필수 해시태그 `#HMG차량용앱개발공모전` 을 포함해 해시태그 2~3개 이상, 링크를 접수 양식 8번에 적는다.
- **숏폼은 아직 만들지 않았다.** 위의 135초 가로 녹화는 숏폼 규격이 아니다. 숏폼을 만든다면 세로로 다시 편집해야 하고, 위 "원칙"과 "고지 문구"를 그대로 지킨다.
- 시연 영상의 제출 방법·길이·형식 규정은 홈페이지에서 찾지 못했다("목업·프로토타입·화면 녹화 인정", 선택 제출).
